## 一、功能梳理

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 开场白 | 用户进入时显示欢迎语+输入格式提示 |
| F2 | 记账（增） | 用户口语输入消费/收入信息，自动解析并存入数据库 |
| F3 | 查询（查） | 按描述、成员、日期查询记录，返回匹配结果 |
| F4 | 按月汇总（查） | 按月统计总支出/收入，返回总额+每条明细 |
| F5 | 删除（删） | 搜索匹配记录→列出→用户确认→删除 |
| F6 | 修改（改） | 找到原记录→显示→用户确认→修改 |
| F7 | 完整性引导 | 缺少关键字段（日期/成员/金额）时追问补充 |
| F8 | 口语化理解 | 闺女→女儿、老爸→爸爸等成员映射 |
| F9 | 调试查看 | 查看调用信息 + 已存数据表 |

## 三、数据库设计

数据库名：`accounting_db`
表名：`money_notes`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT AUTO_INCREMENT | 主键 |
| member | VARCHAR(20) NOT NULL | 成员：爸爸/妈妈/女儿 |
| date | DATE NOT NULL | 日期 |
| type | VARCHAR(10) NOT NULL | 支出/收入 |
| category | VARCHAR(50) | 类别：买书/鞋/护肤/餐饮等 |
| description | VARCHAR(200) | 描述 |
| amount | DECIMAL(10,2) NOT NULL | 金额（正数） |
| created_at | DATETIME DEFAULT NOW() | 创建时间 |

## 四、Prompt设计要点

1. **核心强化指令**：在任何情况下，你都要调用数据库'money_notes'
2. **成员映射**：爸爸/父亲/老爸→爸爸，妈妈/母亲/老妈→妈妈，女儿/闺女/孩子→女儿
3. **日期处理**：今天=当天日期，昨天=前一天，默认今天
4. **输出格式**：必须且只能输出JSON，包含action、fields、confirm等字段
5. **关键词保底**：代码层检测"删除/删掉/去掉"等关键词，强制走delete路径，不完全依赖LLM判断
