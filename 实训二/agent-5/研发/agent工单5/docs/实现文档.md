# 招股书数据问答智能体 - 实现文档

> 工单编号：人工智能NLP-Agent数字人项目-招股书数据问答智能体任务

---

## 一、项目概述

基于80份招股书PDF数据，构建一个RAG（检索增强生成）问答系统。用户输入问题后，系统从招股书中检索相关文档片段，结合大语言模型生成准确答案。

---

## 二、技术架构

```
用户问题
    ↓
m3e-base 向量化
    ↓
Milvus 向量检索（top-5）
    ↓
bge-reranker 重排序（取top-3）
    ↓
拼接Prompt（问题 + 检索片段 + 约束规则）
    ↓
DeepSeek LLM 生成答案
    ↓
输出 JSONL 文件
```

```cmd

```

1. 读取pdf_txt_file/下80个TXT文件

执行过程：

2. 逐条进行向量检索+重排序+LLM生成

预计耗时：30-60分钟（取决于API响应速度）

输出文件：`output/answer.jsonl`

## 五、关键设计决策

### 5.1 为什么用TXT而不是PDF？
工单提供了已解析好的TXT文件（44MB），直接使用可以跳过PDF解析步骤，节省时间且避免解析错误。

### 5.2 为什么选择512字符分块？
- 招股书是正式文档，段落结构清晰
- 512字符约等于一个完整段落，保留了足够的上下文
- 100字符重叠保证跨段落信息不丢失

### 5.3 为什么要用Reranker？
向量检索（embedding相似度）是粗筛，reranker是精排。bge-reranker对（问题, 文本）对进行交叉编码，精度远高于向量相似度，可以显著提高检索准确率。

### 5.4 为什么用Milvus而不是FAISS？
Milvus是专业向量数据库，支持持久化存储、索引管理、多用户访问。虽然FAISS更轻量，但Milvus更适合生产环境。

## 六、过程中遇到的问题及解决方案

### 问题1：question.json格式问题
工单要求提交JSONL格式，但question.json实际就是JSONL格式（每行一个JSON对象），无需额外转换。

### 问题2：问题混合类型
question.json中包含两类问题：
- 招股书相关问题（如"XX公司的发起人有哪些"）
- 基金/股票数据问题（如"涨跌幅最大的股票代码"）

本系统专注于招股书问答，基金/股票类问题可能返回"未找到相关信息"，这是正常行为。

### 问题3：大文件内存占用
80份TXT文件总计44MB，分块后可能产生数万条记录。采用批量编码（batch_size=32）控制内存占用。
