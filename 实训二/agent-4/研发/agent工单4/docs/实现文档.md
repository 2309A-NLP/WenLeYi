# 基金数据问答系统 - 实现文档

## 工单编号：人工智能NLP-Agent数字人项目-基金问答智能体任务

---

## 一、项目概述

### 1.1 任务目标
基于大语言模型（LLM）构建一个基金数据问答系统，能够回答关于基金、股票、债券等金融数据的自然语言问题。

### 1.2 技术方案
采用 **NL2SQL（Natural Language to SQL）** 架构：
- 用户输入自然语言问题
- LLM（DeepSeek）将问题翻译成SQL语句
- SQL在SQLite数据库上执行查询
- 返回精确的答案

### 1.3 数据来源
- **SQLite数据库**：博金杯比赛数据.db（1.46GB，10张表）
- **招股书PDF**：80份招股说明书（已解析为txt）

1. 安装Python依赖（requests、flask、pymilvus等）

8. **chat.py** - 命令行交互界面

### 步骤4：测试与优化
1. 测试前20道题，分析错误类型

4. 添加SQL查询超时限制（30秒）

## 三、遇到的问题及解决方案

### 问题1：字段名包含括号导致SQL错误
**现象**：LLM生成的SQL使用 `a.收盘价` 而非 `a."收盘价(元)"`
**原因**：数据库字段名包含括号，SQLite要求用双引号包裹
**解决**：在prompt中明确标注字段名格式，并在Schema中使用双引号

### 问题2：复杂查询超时
**现象**：JOIN两个大表（1100万行×290万行）的查询执行超过10分钟
**原因**：SQLite查询没有执行超时限制
**解决**：使用threading实现查询超时机制（30秒），超时自动跳过

### 问题3：招股书问题无法回答
**现象**：涉及公司详情、专利、业务模式等问题直接跳过
**原因**：这些信息在PDF文件中，不在SQLite数据库里
**解决**：开发PDF解析模块，从txt文件提取内容，调LLM生成答案

### 问题4：API调用被限流
**现象**：连续调用DeepSeek API时出现429错误
**原因**：请求频率过高触发限流
**解决**：添加请求间隔（0.3秒），失败时自动重试

### 问题5：数据库查询结果重复
**现象**：同一条记录出现多次
**原因**：数据库本身存在重复数据
**解决**：在结果格式化时自动去重

## 四、系统架构

```
用户输入问题
    ↓
问题分类（简单/复杂/招股书）
    ↓
构建Prompt（Schema + 规则 + Few-shot）
    ↓
调用DeepSeek API生成SQL
    ↓
执行SQL查询（SQLite / 30秒超时）
    ↓
格式化答案（去重、分点显示）
    ↓
返回答案给用户
```

## 五、测试结果

- 总题数：1000道

### 5.2 失败原因分析
| 原因 | 数量 | 说明 |
|------|------|------|
| 查询超时 | ~100 | 复杂JOIN查询超过30秒 |
| SQL生成失败 | ~50 | LLM未能生成正确SQL |
| 招股书无对应PDF | ~60 | 公司不在80份PDF中 |
| 字段/表名错误 | ~30 | LLM用了不存在的字段 |
