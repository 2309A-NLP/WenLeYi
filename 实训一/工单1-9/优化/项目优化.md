# Graph RAG 金融问答系统 — 项目优点分析

---

## 一、项目概述

本项目是一个面向金融领域的 Graph RAG（检索增强生成）问答系统，集成了 **混合检索、知识图谱增强、大语言模型生成** 三大核心能力，构建了从文档处理到智能问答的完整链路。系统采用模块化架构设计，具备高扩展性、高可用性和生产级的工程质量。

**核心技术栈：**
- **检索引擎：** BM25 关键词检索 + Milvus 向量检索 + Neo4j 图谱检索（三路并行融合）
- **重排模型：** bge-reranker-base（精度重排）
- **大语言模型：** 支持 OpenAI 兼容 API（mimo-v2.5 / GPT-3.5 等）
- **存储层：** Milvus（向量库）+ Neo4j（图数据库）+ Redis（短期记忆）+ MySQL（持久化）
- **Web 框架：** Flask + SSE 流式输出
- **前端可视化：** vis.js 知识图谱交互式展示

## 二、架构优势

### 2.1 三路混合检索 + 并行执行

| 检索方式 | 技术实现 | 优势 |
|---------|---------|------|
| BM25 关键词检索 | 基于 jieba 分词的 TF-IDF 评分 | 精确匹配专有名词、数值、日期 |
| 向量语义检索 | Milvus / FAISS + Embedding 模型 | 捕捉语义相似性，理解同义表述 |
| Neo4j 图谱检索 | Cypher 查询 + 多跳遍历 | 挖掘实体间隐含关系链路 |

- **并行执行：** 通过 `ThreadPoolExecutor` 同时发起三路检索请求，显著降低总检索延迟
- **加权融合：** 对各路结果进行 Min-Max 归一化后按可配置权重（默认 BM25:0.4 / 向量:0.6 / 图谱:0.3）加权求和
- **多维去重：** 以"文本前 150 字符 + 来源类型"为键进行去重，确保同一文档块的多路分数可累加，增强置信度
- **来源贡献统计：** 运行时自动统计 BM25、向量、图谱、多源融合四类结果的占比，方便调优权重

### 2.2 Neo4j 知识图谱增强

- **多跳遍历（1-hop + 2-hop）：** 先匹配查询直接相关的三元组，再沿实体关系展开第二跳邻居，挖掘深层关联
- **图谱上下文注入：** 将三元组（source → relation → target + evidence）格式化后注入 LLM prompt，引导模型结合实体关系进行推理
- **分数衰减机制：** 第一跳结果赋分 0.5，第二跳结果赋分 0.3，自然衰减避免低相关性结果过度影响
- **图谱可视化：** 基于 vis.js 生成交互式 HTML，支持节点分类（公司/金融产品/财务指标/地区等 8 类）、点击查看详情、搜索过滤

### 2.3 模块化 & 可插拔设计

- 所有核心组件（检索器、Reranker、图谱、Redis、MySQL、JWT、内容过滤）均支持通过 `.env` 配置文件独立开关
- 各模块间通过依赖注入松耦合，便于替换和升级
- 支持多种向量后端切换：FAISS（本地轻量）/ Milvus（分布式生产）

### 2.4 多级缓存架构

```
请求 → Redis 精确命中 → 进程内 LRU 热缓存 → Milvus 相似度匹配（阈值 0.999）→ 实际检索
```

- **Redis 短期记忆：** 按 session_id 存储最近对话轮次，支持 TTL 过期（默认 7 天）
- **进程内 LRU 缓存：** OrderedDict 实现，最大 256 条，避免重复数据库查询
- **Milvus QA 相似度缓存：** 通过 QuestionStore 存储历史问答向量，相似度 ≥ 0.999 时直接返回缓存答案
- **智能缓存管理：** 支持 `forget_question` API，可按需清除指定问题的缓存

## 三、技术优势

### 3.1 Reranker 精度重排

- 使用 **bge-reranker-base** 模型对混合检索结果进行二次精排
- 支持本地模型加载和 API 远程调用两种模式（通过 RERANKER_MODEL_PATH 切换）
- **动态阈值过滤：** 以最高分的 30% 为阈值，过滤低相关性文档块，同时保留至少 1 条结果
- 有效提升 Context Precision，减少无关内容对 LLM 生成的干扰

### 3.2 Query Rewrite（查询改写）

- 针对多轮对话中的**指代消解**问题（"它"、"这个"、"那"等），自动改写为独立完整的问题
- **智能触发机制：** 仅在检测到指代词或问题过短（≤12 字符）时才触发 LLM 改写，避免不必要的额外调用
- 改写后的独立问题同时展示在 prompt 中，增强用户透明度

### 3.3 SSE 流式输出

- 基于 **Server-Sent Events** 实现逐块流式输出，首 token 响应延迟极低
- 流式输出过程中自动清洗 Markdown 格式符号（`*`、`` ` ``、`#`），确保前端显示整洁
- 支持单轮和多轮两种流式接口（`/api/query-stream`、`/api/query-stream-multi`）
- 缓存命中时也以分块方式流式输出（每 12 字符一块，模拟打字效果），保持前端体验一致

### 3.4 多轮对话 & 长上下文管理

- Redis 存储按 session 隔离的对话历史，支持跨会话持久化
- 可配置最大历史轮次（默认 3 轮），自动截断过长历史
- 内置 **LLM 总结旧历史** 能力（`summarize_old_history`），应对超长对话场景
- 进程内历史作为 Redis 不可用时的降级方案，保证系统始终可用

### 3.5 多层兜底机制

| 兜底场景 | 处理策略 |
|---------|---------|
| 检索结果为空 | 返回 `NO_INFO_RESPONSE`（可配置） |
| LLM 回答"未找到"但实际有检索结果 | 强制使用检索内容构建兜底答案 |
| LLM 流式输出为空 | 触发非流式补答，再转为流式输出 |
| LLM 调用失败 | 返回错误提示，不缓存错误结果 |
| 结构化答案命中（如组织架构图） | 跳过 LLM，直接返回结构化结果 |
| Redis 不可用 | 降级到进程内历史 |

### 3.6 Vision LLM 图片问答

- 支持上传 Base64 图片结合文字提问
- 使用独立的 Vision LLM（可单独配置 API 密钥和端点）
- Vision LLM 不可用时自动降级到普通 LLM
- 图片问答同样支持多轮对话上下文

### 3.7 内容安全

- **JWT 鉴权：** 基于 token 的登录认证，支持可配置有效期（默认 24 小时）
- **敏感词过滤：** 可配置屏蔽词列表，拦截包含敏感内容的查询
- **HTTPS 加载：** 支持自签名证书自动生成，保障传输安全
- API 密钥在日志中自动遮蔽（仅显示首尾字符）

### 3.8 模型预加载

- 启动时预加载 Embedding 模型和 Reranker 模型
- 消除首次查询的冷启动延迟，确保用户首次提问即可获得快速响应

### 3.9 增量索引更新

- 文件上传接口（`/api/upload`）支持增量更新向量索引和 Neo4j 图谱
- 自动重建 BM25 索引，无需重启服务
- 支持 PDF、DOCX、DOC、TXT 多种文档格式

## 四、评估体系

### 4.1 RAGAS 风格评估框架

本项目实现了类 RAGAS 的评估框架，采用 **LLM-as-Judge** 方法进行自动化评估：

| 评估指标 | 计算方式 | 目标值 |
|---------|---------|-------|
| **Context Precision** | LLM 判断检索上下文中与参考答案相关的片段比例 | ≥ 0.8 |
| **Context Recall** | LLM 判断检索上下文对参考答案信息的覆盖程度 | ≥ 0.9 |
| **响应时间** | 检索 + Rerank + LLM 生成的总耗时 | ≤ 3s |

### 4.2 评估流程

1. 从 `sample_questions.pdf` 自动提取问题和参考答案
2. 逐题执行检索 → Rerank → LLM 生成 → 计时
3. 对每题调用 LLM-as-Judge 分别评估 Precision 和 Recall
4. 汇总所有题目的平均指标，输出完整评估报告（JSON 格式）
5. 支持 `--before` / `--after` / `--compare` 参数进行优化前后对比

### 4.3 评估结果管理

- 评估结果自动保存到 `results/eval_*.json`，包含逐题详情和汇总统计
- 支持自定义标签（`--tag`），方便实验管理
- 内置对比报告功能，以表格形式展示优化前后各指标的变化和达标情况

## 五、工程优势

### 5.1 配置集中管理

- 所有参数通过 `.env` 文件统一管理，支持环境变量覆盖
- 启动时自动打印完整配置日志（`Config.log_config()`），包含所有参数值
- API 密钥等敏感字段自动遮蔽

### 5.2 完善的日志系统

- 每个模块使用独立日志前缀（`[RETRIEVER]`、`[GRAPH]`、`[RAG]`、`[APP]`、`[EVAL]` 等）
- 关键操作均记录耗时，便于性能分析和瓶颈定位
- 检索融合过程详细记录各路结果数量、来源分布、权重配置

### 5.3 健壮的错误处理

- 所有外部服务（Milvus、Neo4j、Redis、MySQL）连接失败时自动降级
- LLM 调用异常时不缓存错误结果，确保系统自愈
- 检索异常被静默捕获，不影响其他检索路径的正常执行

### 5.4 可观测性

- 每次查询输出完整的执行日志链：缓存检查 → 查询改写 → 检索 → Rerank → 过滤 → Prompt 构建 → LLM 生成 → 缓存存储
- 自动统计和打印耗时、结果数量、分数分布等关键指标
- 评估框架支持逐题详情和批量汇总两种维度的报告

## 六、总结

本项目在以下方面表现突出：

1. **检索质量：** 三路混合检索 + Reranker 精排 + 图谱增强的多层检索架构，确保高 Precision 和高 Recall
2. **响应速度：** 并行检索、多级缓存、模型预加载等策略，有效控制端到端响应时间
3. **系统鲁棒性：** 多层兜底机制和优雅降级策略，确保在各种异常场景下仍能返回有用结果
4. **工程规范：** 模块化设计、集中配置、完善日志、增量更新，具备生产级工程质量
5. **评估闭环：** RAGAS 风格的自动化评估框架，支持优化前后的量化对比
6. **功能完整度：** 涵盖多轮对话、图片问答、知识图谱可视化、JWT 鉴权、内容过滤等生产级特性

该系统不仅满足工单9的技术指标要求（Context Precision ≥ 0.8, Context Recall ≥ 0.9, 响应时间 ≤ 3s），更在架构设计和工程质量上展现了较高的专业水准。
