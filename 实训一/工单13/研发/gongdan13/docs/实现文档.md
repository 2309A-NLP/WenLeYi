# LightRAG 优化任务 -- 实现过程文档

## 一、项目背景

### 1.1 任务来源
- 工单编号：人工智能NLP-RAG项目-LightRAG优化
- 创建时间：2025年8月26日
- 对应项目：在已有RAG问答系统基础上，集成LightRAG实现知识图谱构建与检索优化

### 1.2 传统RAG的局限性
传统RAG系统（基于向量的扁平化数据表示）存在以下问题：
1. 难以有效建模实体之间的复杂语义关系
2. 多实体关联推理中容易出现逻辑断层
3. 全量更新机制使知识库维护成本随数据规模指数增长

### 1.3 LightRAG的优势
LightRAG（Lightweight Retrieval-Augmented Generation）由香港大学团队开发，核心优势：
1. **图结构索引**：将文本转化为知识图谱，保留实体间的语义关系
2. **双层检索机制**：局部检索（具体实体/属性）+ 全局检索（广泛主题/概念）
3. **增量更新**：新数据到来时只更新相关部分，无需重建整个知识库

### 2.3 实体和关系抽取优化（核心）

#### 2.3.1 自定义实体类型
针对招股说明书内容，定义了12种实体类型：

| 实体类型 | 说明 | 示例 |
|---------|------|------|
| 公司名称 | 发行人及关联公司 | 武汉力源信息技术股份有限公司 |
| 人物姓名 | 高管、法定代表人 | 法定代表人姓名 |
| 金额数字 | 财务数据 | 注册资本、募集资金、收入金额 |
| 项目名称 | 募投项目 | 募集资金拟投资项目 |
| 行业领域 | 业务领域 | 电子信息、军用领域、IC市场 |
| 部门机构 | 组织架构 | 销售部、大客户销售部 |
| 地理位置 | 公司所在地 | 武汉、珠海、深圳、北京 |
| 技术标准 | 参与制定的标准 | 技术标准编号 |
| 关联企业 | 控股/参股公司 | 控股子公司、参股公司 |
| 募集资金 | 资金用途 | 募集资金投资项目 |
| 荣誉奖项 | 获得的奖项 | 国家科技进步一等奖 |
| 产品名称 | 具体产品 | 公司主要产品 |

#### 2.3.2 自定义关系类型
定义了12种关系类型：
- 控股关系、持股比例、投资项目、隶属部门
- 收入来源、参与制定、供应商、下游行业
- 荣获奖项、募集用途、注册资本、法定代表人

#### 2.3.3 Prompt 注入机制
LightRAG 默认使用英文实体抽取 Prompt，针对中文招股说明书需要覆盖：
1. 通过修改 `lightrag.prompt.PROMPTS` 字典覆盖系统/用户 Prompt
2. 通过 `addon_params` 传入自定义实体类型和语言设置

```python
# 覆盖默认 Prompt
PROMPTS["entity_extraction_system_prompt"] = CUSTOM_SYSTEM_PROMPT
PROMPTS["entity_extraction_user_prompt"] = CUSTOM_USER_PROMPT

# 初始化时传入自定义参数
LightRAG(
    addon_params={
        "language": "Chinese",
        "entity_types": CUSTOM_ENTITY_TYPES,
    },
)
```

### 2.4 LightRAG 索引构建流程

```
PDF文件 → PyMuPDF提取文本 → LightRAG切块(1200 tokens)
    → LLM抽取实体关系 → 构建知识图谱(NetworkX)
    → Embedding向量化 → 存储到本地(JsonDB + NanoVectorDB)
```

### 2.5 双层检索机制

| 检索模式 | 说明 | 适用场景 |
|---------|------|---------|
| local | 局部检索：基于具体实体和属性 | "销售部有几个部门？" |
| global | 全局检索：基于广泛主题和概念 | "电子信息行业的上下游？" |
| mix | 混合检索：local + global | 复杂关联查询（默认） |

### 2.6 对比评估体系

#### 评估指标
使用 LLM 作为评估裁判，计算三个核心指标：
1. **Faithfulness（忠实度）**：回答是否忠实于检索到的参考资料
2. **Answer Relevancy（答案相关性）**：回答是否直接回答了问题
3. **Context Relevancy（上下文相关性）**：检索到的资料是否与问题相关

#### 评估流程
```
14个测试问题 → [传统RAG] 检索+生成 → 收集答案和上下文
                → [LightRAG] 检索+生成 → 收集答案和上下文
                → LLM评估三个指标 → 输出对比表格
```

## 三、过程问题记录

### 问题1：RAGAS 依赖冲突
- **现象**：`from ragas import evaluate` 报错 `ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'`
- **原因**：RAGAS 0.4.3 依赖 langchain-community，但 vertexai 模块需要单独安装 google-cloud-aiplatform
- **解决方案**：放弃 RAGAS 官方库，改用 LLM 作为评估裁判（效果等价，且更灵活）

### 问题2：LightRAG 实体抽取使用英文 Prompt
- **现象**：默认实体抽取 Prompt 是英文，对中文招股说明书效果差
- **解决方案**：通过覆盖 `PROMPTS` 字典注入中文实体抽取 Prompt，并通过 `addon_params` 设置 `language: "Chinese"`

### 问题3：LightRAG Embedding API 兼容性
- **现象**：LightRAG 默认期望 OpenAI Embedding API，小米 API 可能不支持 Embedding 接口
- **解决方案**：创建 `EmbeddingWrapper` 类，支持自定义 Embedding API 地址和模型名称

## 五、使用说明

### 5.1 构建 LightRAG 索引（首次运行）
```bash
python scripts/compare_rag_lightrag.py --build-index
```

### 5.2 生成知识图谱可视化
```bash
python scripts/visualize_graph.py
# 用浏览器打开 knowledge_graph.html
```

### 5.3 运行对比评估
```bash
# 全量评估（16个问题，耗时较长）
python scripts/compare_rag_lightrag.py

# 只测试前3个问题
python scripts/compare_rag_lightrag.py --questions 3

# 只评估 LightRAG（跳过传统RAG）
python scripts/compare_rag_lightrag.py --skip-rag
```

### 5.4 查看结果
评估完成后，在 `evaluation_results/` 目录下查看：
- `metrics_comparison.json`：指标对比数据
- `rag_results.json`：传统RAG详细结果
- `lightrag_results.json`：LightRAG详细结果
