======================================================
        gongdan10 RAG 项目 — 已实现的优化与优点
======================================================


一、检索架构优化
------------------------------------------------------
1. 三路混合检索（HybridRetriever）
   - BM25 关键词检索 + 向量语义检索 + Neo4j 知识图谱检索
   - 三路并行执行（ThreadPoolExecutor），不阻塞
   - 加权融合：BM25(0.4) + 向量(0.6) + 图谱(0.3)
   - 使用 RRF（Reciprocal Rank Fusion）排名融合算法
   - 分数 Min-Max 归一化后融合

2. Reranker 精排
   - 混合检索后使用 Cross-Encoder 模型二次排序
   - 模型：bge-reranker-base（本地推理，无网络依赖）
   - 从 top_k=8 精排到 top_k=3，提升精度

3. QA 缓存命中
   - 历史问答相似度匹配（阈值 0.999）
   - 相似问题直接返回缓存答案，秒级响应
   - 避免重复调用 LLM，节省 API 费用


二、文档处理优化
------------------------------------------------------
4. 完整的文本清洗流水线
   - 去水印、保密标记、装饰符号
   - 去页眉页脚、页码
   - 去特殊字符、乱码
   - 清理表格噪音
   - 提取正文（去目录/声明/附录）
   - CJK 兼容字符归一化

5. 多格式文档解析
   - PDF（pdfplumber + PyMuPDF 双引擎）
   - DOCX（python-docx）
   - TXT 纯文本

6. 图片提取 + 视觉理解
   - 从 PDF 中提取嵌入图片
   - 调用视觉大模型（mimo-v2.5 Vision）生成图片描述
   - 多模态内容理解

7. 并行文档处理
   - ThreadPoolExecutor 并行解析多个文档
   - 可配置工作线程数（DOC_PROCESS_WORKERS）


三、模型与推理优化
------------------------------------------------------
8. 本地 Embedding 模型
   - m3e-base（768维向量，中文优化）
   - 本地推理，无网络延迟
   - 启动时预加载，首次查询零延迟

9. 本地 Reranker 模型
   - bge-reranker-base（Cross-Encoder）
   - 本地推理，隐私安全
   - 启动时预加载

10. LLM 流式输出
    - SSE（Server-Sent Events）流式响应
    - 用户实时看到回答生成过程
    - 体验优于等待完整回答

11. 视觉模型支持
    - Vision LLM 支持图片输入
    - 图片描述与文本问答融合


四、对话与记忆优化
------------------------------------------------------
12. 多轮对话记忆
    - 保留最近 10 轮对话历史
    - 上下文连贯的连续问答

13. Redis 短期记忆
    - 对话历史持久化到 Redis
    - TTL 7 天自动过期
    - 按 session_id 隔离不同用户

14. 历史问题检索
    - QA 缓存相似度匹配
    - 高频问题秒级返回
    - 减少 LLM 调用次数


五、安全与过滤优化
------------------------------------------------------
15. JWT 鉴权（可选）
    - 自实现 HS256 JWT，无额外依赖
    - Token 过期时间可配置
    - 保护 API 接口

16. 屏蔽词过滤（可选）
    - 用户输入敏感词检测
    - 可配置屏蔽词列表
    - 拦截后返回友好提示

17. API Key 脱敏
    - 日志中自动遮蔽 API Key
    - 只显示前 6 位和后 4 位


六、部署与运维优化
------------------------------------------------------
18. Docker 容器化部署
    - Dockerfile 一键构建
    - 阿里云 apt/pip 镜像加速
    - PyTorch CPU 专用镜像（减小体积）

19. 环境配置分离
    - .env.docker 与 .env 独立配置
    - Docker 环境使用 host.docker.internal 访问宿主机服务
    - 不修改原始代码

20. 模型挂载（只读）
    - 本地模型目录挂载进容器
    - 不重复打包模型，镜像体积小
    - 模型更新无需重新构建

21. 数据持久化
    - documents/、uploads/、vector_store/ 挂载到宿主机
    - 容器重建不丢数据


七、代码质量优化
------------------------------------------------------
22. 模块化设计
    - 13 个独立 core 模块，职责清晰
    - 每个模块可独立测试和替换
    - 松耦合，易扩展

23. 配置集中管理
    - 所有参数统一在 config.py 管理
    - 支持 .env 文件和环境变量
    - 启动时打印完整配置日志

24. 详细日志输出
    - 每个模块带 [前缀] 日志
    - 启动时打印配置详情
    - 检索/生成过程可追溯

25. 错误处理
    - 外部服务连接失败优雅降级
    - Redis/Neo4j/MySQL 不可用不影响核心功能
    - Milvus 重试机制


八、功能完整性
------------------------------------------------------
26. 完整的 RAG 流程
    - 文档解析 → 清洗 → 分块 → 向量化 → 存储
    - 查询 → 缓存检查 → 混合检索 → 精排 → LLM 生成

27. 知识图谱增强
    - Neo4j 图谱检索补充语义关系
    - 三元组查询增强回答准确性

28. 多模态支持
    - PDF 图片提取 + 视觉模型描述
    - 图文结合的问答能力

29. 模型微调支持
    - finetune/ 目录包含完整微调流程
    - 支持 AutoDL 云端训练
    - 数据集自动生成

30. 文件上传功能
    - 用户可上传新文档
    - 自动触发索引重建
